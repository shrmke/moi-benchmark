# Astra 969550b、Hermes、Pi 与 DSH：Toolathlon 108 题对比分析

生成日期：2026-09-15

## 口径

- 固定 108 个任务，按任务名称对齐，每个框架每题采用一个选定执行结果。
- Astra 为 80 pass / 28 no_pass：包含四题跨版本历史替代（3 pass、1 no_pass）。时间、工具、模型请求和 Token 均纳入这四题历史数据。本对比不携带去除四题的补充列。
- Pi 为 104 个明确 Evaluator 结果、3 个 unavailable、1 个 incomplete；不把后四题归为 no_pass。
- 全部 Token 和 Pass Token 均采用可见 usage 下界，不再筛选整题 usage 完整性；缺失不是零，历史与本轮请求内部结构也不同。
- 各框架运行时段、网络状态、模型凭据、重试与恢复策略不同；这是选定结果对比，不是同一环境瞬时状态下的受控实验。

## 综合结论

1. 按 108 题主口径，Astra 为 **80 pass（74.07%）**，DSH 为 79（73.15%），Pi 为 77（71.30%），Hermes 为 72（66.67%）。Astra 比 DSH 多 1 个选定 pass，但含历史与离线替代；Pi 仍有 4 题无明确结果，不能据此作无条件能力排名。
2. Astra 的 28 个 no_pass 中，26 个为完成后交付未满足 Evaluator，2 个达到请求预算（含 1 个历史替代）。Hermes、Pi、DSH 分别为 36、27、29 个 no_pass。
3. Astra 选定执行 Agent 时间合计 20.71 h，高于 Hermes 14.21 h、Pi 15.90 h、DSH 14.44 h；这不是相同任务成功集合下的速度比较，也不包含所有历史尝试与运维成本。
4. 统一采用可见 Token 下界后，Astra 为 262,933,666，Hermes 为 248,085,639，Pi 为 239,988,812，DSH 为 142,673,137。网络中断、内部请求、上下文、缓存以及缺失 usage 均影响这些数值，不能视为完整账单。
5. 四框架采用统一的选定结果及可见 Token 下界口径；各自运行批次、恢复策略与通过任务集合不同，资源消耗不包含所有历史尝试与人工运维成本。
