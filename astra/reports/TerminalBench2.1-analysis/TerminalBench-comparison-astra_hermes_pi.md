# Astra、Hermes 与 PI：Terminal-Bench 2.1 任务完成结果汇总

生成日期：2026-08-14
比较对象：Astra、Hermes、PI 在同一 Terminal-Bench 2.1 任务集上的最新运行记录。

## 统计口径

- 每个产品、每个任务只取其输入汇总 CSV 已选定的最新一次验证记录。
- 三方横向比较主样本为 **83 个严格配对任务**：仅保留三个产品均有 `verify_status` 的任务。
- `verify pass` 表示 verifier 通过；`no-pass` 表示有 verifier 结果但未通过。
- 正常端到端成功定义为 `verify pass` 且无 timeout；因此“通过但发生 timeout”单独列示。
- 时间、工具调用与 token 均来自各产品的任务汇总字段。不同产品的工具和 token 采集实现不同，相关数值用于描述运行负担，不直接构成效率或成本排名。
- 不统计美元成本；不使用测试明细作为比较指标。

## Token：已观测用量与可比性边界

下表只统计具有完整输入、输出和 total 字段的记录。PI 的 total 为 input + cache + output；Astra 的 total 为**主 Agent**已保存的 token，**不包含 Intent Judge**；Hermes 的 total 来自 `hermes-run.json.usage`。因此，三方 total 不应被解释为完整的、严格可比的端到端 token 成本。

| 产品              | 完整 token 记录覆盖 | 输入 token 总量 | 缓存 token 总量 | 输出 token 总量 | total token 总量 | 平均 total token |
| ----------------- | ------------------: | --------------: | --------------: | --------------: | ---------------: | ---------------: |
| Astra（主 Agent） |             80 / 83 |      27,704,040 |          未单列 |       3,276,544 |       30,980,584 |          387,257 |
| Hermes            |             74 / 83 |      84,706,852 |          未单列 |       1,877,321 |       86,584,173 |        1,170,056 |
| PI                |             83 / 83 |      89,789,880 |      83,457,280 |       3,510,471 |      176,757,631 |        2,129,610 |

在通过任务中，完整 token 记录分别为 Astra 41 条、Hermes 45 条、PI 52 条；对应已观测 total token 分别为 15,337,153、39,658,727、87,965,314。Astra 的数值仍缺少 Intent Judge 调用的 usage，不能以当前历史轨迹准确补齐；Judge 的调用次数可能接近主 Agent 的轮次数，但其实际输入、输出和缓存 token 未被保存。故 token 部分只用于展示各产品当前可观测用量，而不据此给出跨产品 token 效率结论。

## 结论

- 在 83 个严格配对任务上，PI 的 verifier 通过率为 62.7%，Hermes 为 56.6%，Astra 为 51.8%。
- 正常端到端成功数依次为 PI 47、Hermes 45、Astra 40；Astra 的 timeout 率为 42.2%，高于 PI 的 15.7% 和 Hermes 的 9.6%。
- 三者在 Hard 任务均出现明显降幅；PI 在这三档作者难度中均不低于其他两者。
- Hermes 的端到端时间中位数最低；工具调用与 token 的实现口径不同，不能据此作产品效率排序。
- Astra token 仅覆盖主 Agent，尚未计入 Intent Judge；因此尤其不能将其 total token 与 Hermes 或 PI 的产品级用量做等值比较。
