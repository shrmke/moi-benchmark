### 维度 4：时间与排期合理性

✅ 已确认：

- 30/60/90 天分别对应 4/8/12 周目标完成点，日历窗口仍保留治理余量。
- 每两周阶段包含 1–2 个工作日缓冲，总体 10–15%。
- 关键路径优先级明确：Contract → Run → Compare/Gate → Bundle → 五域接入 → 服务化 → Pilot。
- Scope cut 顺序明确：先后移 Dashboard 美化、次要 Copilot、非主 Pilot；不削减 Gate、Bundle 和证据完整性。
- 资源不再假设三客户 Pilot 同时启动。
- 里程碑均有可执行验收标准和退出条件。

⚠️ 持续校准项：2 FTE + 0.5 FTE Owner、专家每周 ≥2 小时、数据 5 个工作日就绪均为内部计划假设，不是历史实测值；首个 Pilot 后必须用实际 throughput 回标。

### 维度 5：抗风险性

✅ 已覆盖：

- MOI/MatrixFlow API 或 Trace 延迟：离线 Artifact Adapter 先行。
- 客户数据/审批/专家延迟：Reference Dataset 保持产品主线，Pilot 从数据就绪日计时。
- 模型/Provider/GPU 波动：冻结 System Card 与 Baseline，环境变化后不做伪对比。
- 关键人员单点：ADR、Contract、双人 review、代理 Owner。
- 测试/fixture 不稳定：Phase 0 清理和隔离。
- 90 天范围超载：明确 Scope cut 顺序。
- 客户数据泄露：本地运行、权限、脱敏、保留期和禁止训练回流。
