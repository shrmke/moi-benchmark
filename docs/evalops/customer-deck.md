## 企业 AI 的持续验证与质量运营平台

让 Document、RAG、NL2SQL、Memory 与 Agent 从“可以演示”走向“可验收、可追溯、可持续改进”

**关键词：** 业务验收 · 持续评测 · 质量门禁 · 证据审计 · 私有化运行

---

# 01｜为什么企业 AI 需要 EvalOps

AI 应用进入生产后，真正困难的已经不是“模型能不能回答”，而是：

- **效果难定义**：不同业务对“正确”的定义不同，通用榜单无法替代客户验收。
- **结果难复现**：模型、Prompt、数据和平台持续变化，同一问题可能得到不同结果。
- **失败难定位**：解析、检索、语义、Agent 编排和工具执行相互影响，最终分数无法说明根因。
- **升级难决策**：新模型或新版本是否更好，常常依赖人工抽查和主观判断。
- **质量难持续**：POC 有效果，不等于每次上线都能保持效果。

> 企业 AI 的核心挑战，正从“构建能力”转向“持续证明能力”。

# 02｜我们的愿景

## 让每一个 AI 能力都有可执行的验收标准

MOI EvalOps 将企业数据、AI 执行与质量验证连接成闭环：

**业务目标** → **场景与 Golden** → **自动运行** → **多维评测** → **失败归因** → **版本优化** → **发布门禁** → **持续回归**

### 三个目标

1. **可验收**：把业务语言转化为数据集、Golden、指标和通过条件。
2. **可追溯**：每个结果可以追溯到数据、模型、配置、版本与原始证据。
3. **可持续**：历史 badcase 自动进入回归资产，阻止同类问题再次进入生产。

# 03｜EvalOps 是什么

EvalOps 是面向企业 AI 全生命周期的质量工程体系，由五部分组成：

| 组成 | 核心内容 | 客户获得的价值 |
|---|---|---|
| 方法论 | 场景拆解、指标设计、Golden 规范、可比性规则 | 确保“测什么、怎么算”有统一口径 |
| 评测资产 | 数据集、任务、Golden、badcase、基线与行业模板 | 把项目经验沉淀为可复用质量资产 |
| 工具平台 | 自动运行、评测、对比、门禁、报告与证据导出 | 降低重复测试和人工分析成本 |
| 运营机制 | 版本回归、失败复盘、质量看板、发布策略 | 让质量管理成为持续过程 |
| AI Copilot | Golden 辅助生成、用例扩展、错误聚类与报告生成 | 加速资产建设与问题定位 |

> EvalOps 不是一次跑分，而是一套持续运转的 AI 质量操作系统。

# 04｜覆盖企业 AI 的五大能力域

### Document Intelligence
文本、标题、表格、公式、图片、阅读顺序、版面和 Excel 专项质量评测。

### RAG
检索命中、证据覆盖、回答忠实度、完整性、引用与拒答质量评测。

### NL2SQL
Schema 理解、SQL 生成、执行结果、业务语义、稳定性与时延评测。

### Memory
写入、检索、更新、版本、分支、回滚、治理与长期记忆能力评测。

### Agent
任务完成率、工具调用、执行轨迹、预算、超时、失败恢复与安全边界评测。

**统一原则：** 优先验证真实任务结果，而不是只用另一个大模型判断“看起来是否正确”。

# 06｜从“一个总分”升级为“可行动的诊断”

传统评测通常只能回答：**得了多少分？**

MOI EvalOps 进一步回答：

- 哪个场景、哪类数据、哪一步开始退化？
- 问题来自模型、业务语义、检索、解析还是 Agent 编排？
- 是普遍问题，还是少数长尾样本？
- 新版本相对 Baseline 改进了什么，又引入了什么？
- 是否满足发布条件？不满足时应由哪个环节处理？
- 结论能否由客户或第三方重新验证？

> 评测的终点不是报告，而是下一步可执行的优化决策。

# 07｜阶段性评测证据与系统价值

## 业务语义可以被量化

在 Enron Eval 50（50 题、每题 3 轮）的统一基础模型与测试条件下，引入 MOI 业务语义后：

- NL2SQL 人工严格正确率：**76.67% → 86.67%**
- 口语化业务问题严格正确率：**62.67% → 82.67%**

## 复杂企业文档能力

在 50 份复杂制造业场景文件的本次三方对比中：

- **42 / 50** 份文件取得最高结果
- **0** 个有效解析失败
- 优势集中于长文档、Office、跨页表格、公式和层级结构

## 可治理的长期记忆

- 快照与回滚：**50 / 50**
- 低置信记忆治理：**50 / 50**
- 分支、Diff 与 Merge：**48 / 50**
- LongMemEval-S（500 题）本地评测：**459 / 500（91.80%）**

*证据索引：Enron Eval 50、复杂制造业文档私有集、LongMemEval-S 与 Memoria Feature 自建集。以上为固定版本和约定测试条件下的阶段性结果，仅代表相应测试集；详细 Run/Report 可按项目提供，客户项目以双方确认的 POC 数据与验收口径为准。*

# 08｜面向客户的三类交付方案

## 方案 A｜AI 能力验收

适用于 POC、产品选型和项目交付。

交付：场景清单、测试集、Golden、指标口径、运行结果、验收报告。

## 方案 B｜持续质量回归

适用于模型、Prompt、知识库或产品频繁升级的生产系统。

交付：Baseline、自动回归、趋势分析、退化告警和发布门禁。

## 方案 C｜AI 质量运营

适用于多应用、多团队和多模型的企业级 AI 平台。

交付：统一资产目录、质量看板、问题闭环、Evidence Bundle 和周期性质量报告。

# 09｜三个可快速启动的场景包

### 企业文档与知识问答

文档 → 解析 → 切分与索引 → 检索 → 回答 → 引用验收

重点验证：复杂格式、证据覆盖、回答忠实度与可追溯引用。

### 业务数据库智能问数

自然语言 → 语义理解 → SQL 生成与修复 → 数据库执行 → 结果集验收

重点验证：业务术语、执行正确率、复杂查询、稳定性与响应时间。

### 企业 Agent 任务执行

任务 → 计划与工具调用 → 执行轨迹 → 任务结果 → 失败恢复验收

重点验证：任务完成率、工具使用、预算、超时、恢复与安全边界。

# 10｜一套可信、可复现的评测过程

按 EvalOps 标准执行时，每次运行形成独立 Run，并冻结：

- Dataset / Task / Golden 版本
- 被测系统、模型与 Provider
- Prompt、配置与运行环境
- Evaluator 与聚合算法版本
- 逐题结果、失败分类与原始工件
- 运行时间、性能、Token 与关键轨迹

### Evidence Bundle

可按项目导出：运行摘要、逐题证据、版本清单、原始产物索引、哈希与脱敏报告。

### 可比性保护

当数据、维度、权重、格式或聚合口径不一致时，不直接生成具有误导性的单值差异。

# 12｜为什么选择 MOI

### 不是只测模型，而是验证真实产品链路
覆盖解析、检索、语义层、Agent 编排、工具执行与最终结果。

### 不是只给分数，而是给出证据与根因
结果可回溯到样本、步骤、配置、版本和原始工件。

### 不是一次性 POC，而是持续质量资产
每次项目、升级和生产问题都会沉淀为新的回归能力。

### 不是通用 Judge，而是行业可执行验收
将客户业务规则转化为 Golden、Verifier 和发布门禁。

> MOI EvalOps：让企业 AI 的每一次升级，都建立在可验证的进步之上。
